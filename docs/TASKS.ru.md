# Как загружать и делать задания

[English](TASKS.en.md) · **Русский**

Задание это один файл `.json`: название, справка и список задач. Программа сама его читает и проверяет решения.

## 1. Как загрузить задание

1. В окне программы внизу слева нажмите «Ещё», потом «Добавить задания из файла» и выберите файл `.json`. Можно выбрать сразу несколько файлов.
2. Или положите файл в папку с заданиями и перезапустите программу. Если запускаете из кода, это папка `Задания/` в репозитории. Если запускаете exe, это `Документы/Практика Python/Задания/`.

Название файла (без `.json`) может состоять только из букв, цифр, пробела, `_` и `-`. Если задание с таким именем уже есть, программа его не перезапишет и скажет об этом. Если в файле ошибка, программа покажет, что именно не так (например, «задача 3: нет текста условия»).

Готовый пример для начала: [`example-task.json`](example-task.json).

## 2. Как попросить сделать задания нейросеть

Если вы не программист, скопируйте запрос ниже в любую нейросеть, замените слова в `[скобках]` и сохраните ответ в файл с расширением `.json`. Потом загрузите его, как описано выше. Если программа пишет ошибку, отправьте её текст нейросети с просьбой исправить файл.

```
Составь учебное задание по Python для новичка в виде одного JSON-файла для программы «Практика Python».
Тема: [например, «цикл for»]. Язык текстов: [русский / английский] (в файле на верхнем уровне поле "lang": "ru" для русского или "en" для английского). Нужно [7] задач.

Формат файла:
- На верхнем уровне: "title" (название), "topic" (тема), "general" (общая памятка «как отвечать», одна на всё задание), "help" (список шагов справки: {"h": заголовок, "t": текст, "code": пример кода}), "questions" (список задач).
- Первый пункт справки: «Урок», где тема объяснена простыми словами на примерах.
- Каждая задача: {"type": "script", "text": условие, "about": "Тренируется: ...", "before": готовая часть кода ДО решения (необязательно), "after": готовая часть кода ПОСЛЕ решения (обычно print(...)), "starter": код, который уже лежит в поле (для задач «поправь готовое»), "expected_output": точный вывод в консоль, "assigns": [имена переменных, которые нужно создать], "uses_names": [имена переменных, которые должны использоваться], "consts": {имя: значение, которое надо положить в переменную}, "required": [знаки + - * / // % ** , которые обязаны быть в решении], "required_text": [фрагменты, которые обязаны быть в коде], "max_text": {фрагмент: сколько раз его можно написать}, "expected_error": "название ошибки, например NameError (вместо expected_output)", "inputs": [ответы на input(), по порядку]}. Нужные поля бери только те, что нужны задаче.
- В тексте можно использовать `код`, **жирный** и ==выделение==. Каждая строка условия: «Что сделать: ...», «Что должно получиться: ...», «Где смотреть: ...».

Правила для задач:
1. Лесенка: сначала 1–2 задачи «повтори пример из урока», потом 1–2 «поправь готовое», потом «напиши своё», в конце задача с ошибкой.
2. Условие говорит, что сделать и что должно получиться, но не подсказывает, как это сделать. Подсказки лежат в справке.
3. Без сложной математики и без текстовых задач со сказкой. Числа маленькие и круглые, считает Python.
4. Простые слова, без лишних терминов. Каждый новый термин объяснён один раз.
5. Проверь, что верное решение каждой задачи действительно выводит expected_output.
Верни только JSON.
```

## 3. Как устроен файл

### Верхний уровень

| Поле | Нужно? | Что это |
|---|---|---|
| `title` | да | название задания (показывается в списке и в заголовке) |
| `topic` | нет | тема, маленькая надпись над названием |
| `lang` | нет | `"ru"` или `"en"`: в каком языке программы показывается задание. Без поля задание видно на обоих языках |
| `general` | нет | общий текст «Как отвечать» (вкладка «О задании»), один на всё задание |
| `help` | нет | вкладка «Справка»: список шагов `{"h": заголовок, "t": текст, "code": пример}` |
| `questions` | да | список задач (не пустой) |

### Задача типа `script` (основной тип)

Программа склеивает `before` + код из поля + `after`, запускает как обычный `.py` файл и сравнивает вывод с `expected_output`.

| Поле | Что делает |
|---|---|
| `type` | `"script"` |
| `text` | условие задачи (обязательно) |
| `about` | короткая строка во вкладке «О задании» («Тренируется: ...») |
| `before`, `after` | готовые части кода до и после. В окне они показаны серым с замочком, менять их нельзя |
| `starter` | код, который уже лежит в поле (для задач «поправь готовое») |
| `placeholder` | серая подсказка в пустом поле |
| `min_lines` | сколько строк показывать в поле (1–30, по умолчанию 3) |
| `inputs` | список ответов на `input()`, по порядку |
| `expected_output` | точный вывод в консоль (пробелы в конце строк и пустые строки по краям не учитываются) |
| `expected_error` | вместо вывода: название ошибки, которую должен вызвать код, например `"NameError"` или `"TypeError"` |
| `required_text` | список фрагментов, которые обязаны быть в коде |
| `max_text` | `{"фрагмент": N}`: фрагмент можно написать в коде не больше N раз (например, чтобы нельзя было набрать результат руками) |
| `assigns` | список переменных, которые должны быть созданы (`имя = ...`) |
| `consts` | `{"имя": значение}`: переменной нужно присвоить именно это значение, записанное прямо (число без кавычек, текст в кавычках) |
| `min_assigns` | `{"имя": N}`: переменной нужно присвоить значение не меньше N раз |
| `uses_names` | список переменных, которые должны участвовать в вычислении, а не быть набраны готовым значением |
| `required` | знаки из `+ - * / // % **`, которые обязаны быть в решении |

Дополнительные типы `expression`, `text`, `code` и `shell` оставлены для совместимости со старыми файлами, новым заданиям они не нужны.

### Разметка текста

В `text`, `t` и `general` можно писать `` `код` ``, `**жирный**`, `__подчёркнутый__` и `==выделенный==`. Каждый перевод строки это новая строка на экране. Метки в начале строки подсвечиваются сами: по-русски `Что сделать:`, `Что должно получиться:`, `Где смотреть:`, `Что дано:`, `Что нужно...:`, `Ограничение:`, `Готовая часть:`, `Важно:`, по-английски `What to do:`, `Expected result:`, `Where to look:`, `Given:`, `Constraint:`, `Ready part:`, `Note:`. Другие метки можно писать жирным.

В `code` справки действуют правила: строка, начинающаяся с `|`, показывается как готовая часть (с замочком), строка, начинающаяся с `→`, показывается как вывод программы, а `# ...` это комментарий.

## 4. Как правильно составлять задания

Это короткий рецепт, по которому сделаны три задания в репозитории. Им не обязательно пользоваться: если вам нравятся сложные задания, пишите их по-своему, формат файла от этого не меняется.

1. **Одна тема за раз.** Берите страницы книги или документации ровно по этой теме и сверяйте с ними термины и примеры.
2. **Сначала «Урок».** Первым пунктом справки: что это такое одной простой фразой, примеры прямо из книги, что значит ошибка, если она бывает в этой теме. Пишите абзацами и простыми словами. Слово из книги объясняйте один раз.
3. **Шаги справки.** Короткие, пронумерованные, в каждом одна мысль. К примерам кода комментарии и стрелка `→` с результатом.
4. **Лесенка из 6–8 задач.** 1–2 задачи «повтори пример из урока руками», 1–2 «поправь готовое» (поле `starter`), потом «напиши своё» с нуля, в конце задача, где нужно прочитать сообщение об ошибке, и одна задача, где всё соединяется вместе.
5. **Условие тремя строками:** «Что сделать», «Что должно получиться», «Где смотреть» (вкладка «Справка», «Урок» и номера шагов). Условие говорит, что нужно, но не подсказывает как. Правила задачи (что нельзя) пишите прямо в «Что сделать».
6. **Лёгкие числа.** Без сложной математики и без задач со сказкой. Числа маленькие и круглые, считает Python. Хорошо подходят задачи про тексты, имена, письма, отчёты и ошибки.
7. **Закройте обходные пути.** Чтобы нельзя было просто набрать готовый ответ, используйте `required`, `required_text`, `max_text`, `uses_names`, `consts`, `min_assigns`.
8. **Проверьте перед выдачей.** Верное решение каждой задачи проходит, неверное нет. Номера шагов в «Где смотреть» совпадают со справкой. Каждый пример из справки работает, если ввести его с нуля.

Так устроено и обучение по исследованиям для новичков: полностью разобранный пример, потом «доделай» и «поправь», потом своё, помощь убирается постепенно.
